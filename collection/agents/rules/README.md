# ~/.agents/rules — shared agent rules (physical SSOT)

> Точка входу до всього `~/.agents` — [`../AGENTS.md`](../AGENTS.md): карта тек, правила, що
> мусять спрацювати до завантаження скіла, і як обрати канал доставки для нового правила.

Фізичне джерело правди для **крос-проєктних** правил/ідіом для агентів (LLM + людина).
Паралельно до `~/.agents/skills/` (скіли) та `~/.agents/*-cheatsheet.md` (шпаргалки).

- **Тут** — правила, спільні для ВСІХ проєктів (TS-ідіоми, загальні архітектурні принципи…).
- **Проєкт-специфічні** правила лишаються в репо (`<repo>/.ai/rules/*.mdc`, `docs/agent/`).

## Доступ з Obsidian
Ця тека **symlink-нута** в global-vault: `~/vaults/global/rules → ~/.agents/rules`.
Тож у кожному project-vault вона видима як `4 - Shared/rules/` і віддається через Obsidian MCP.
Редагуй файли **тут** (фізичне джерело); Obsidian показує їх через symlink.

## Як правило доходить до застосування

Файл тут — це **джерело**, не доставка. Правило спрацьовує лише тоді, коли щось приводить агента
до нього **в потрібний момент**:

| Канал | Коли читається | Що туди класти |
|---|---|---|
| [`../AGENTS.md`](../AGENTS.md) | точка входу, вендор-нейтральна | те, що мусить спрацювати на прямому виклику інструмента |
| `~/.claude/CLAUDE.md` | **кожна сесія** Claude Code, до будь-якого скіла | лише вказівник на `AGENTS.md` + мінімум, що має діяти без другого читання |
| скіл (`~/.agents/skills/…`) | коли скіл викликано | те, що належить конкретному етапу конвеєра |
| `<repo>/AGENTS.md` | кожна сесія в тому репо | репо-специфічне |

🔴 **Правило без каналу дорівнює відсутньому.** Перевірено на `agent-stream-to-file`: воно
існувало, було докладним і не застосовувалось, бо єдиним його каналом були скіли — а агенти
запускались напряму.
