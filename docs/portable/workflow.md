# One proportional workflow

User scope and runtime permissions bound all work. Accepted local contracts and ADRs define desired behavior; code and scripts show actual behavior. Record contradictions with both sources. Correct an unambiguous bug within authorized scope; ask the contract owner when requirements conflict or a policy change is proposed.

1. Identify the exact root, branch/HEAD, relevant dirty/untracked files, current instructions, task owner and acceptance criteria. Never reset somebody else's work.
2. Choose small/full/resume using the local rules. Small work uses one primary record, a short plan and applicable checks. Full work adds explicit acceptance, risks/rollback and independent critique/review when required. Resume validates the named handoff and current evidence before repeating work.
3. Choose exact skill files only when relevant. Native discovery and exact-file fallback are different evidence states. Missing tools do not authorize installation. An unavailable required reviewer is BLOCKED; author checks are not independent review.
4. Implement only the approved change. Before any test/build command, inspect transitive effects, including reset/seed/generation/services/network. Coordinate shared resources. Existing required gates remain binding until their owner changes them.
5. Record PASS/FAIL/BLOCKED/N/A with command/scenario, snapshot and evidence. UI changes need actual render/interaction evidence; compilation is not browser QA. Review receives pinned scope/diff, acceptance and raw evidence in a separate context.
6. Close or hand off in the existing record: goal, scope, sources, revision/dirty state, decisions, checks, blockers, next owner/action. Select exact handoff paths/IDs, not latest-note guesses. Archive/commit/push/deploy only under the local process and user authorization.

Create an ADR for a consequential lasting choice with real alternatives and future behavioral impact under local criteria. A small fix, TODO or implementation summary does not automatically need an ADR. Keep project ADRs in their repository; external notes link to them.

Graph tools provide navigation candidates. Verify provenance/freshness and consequential claims in source; do not merge unrelated graph databases or substitute graph scores for tests/review.
